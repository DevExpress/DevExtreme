What changed. fluent-next carries no blanket dim: a disabled component paints itself from the disabled roles, the way Fluent specifies and the way Blazor's themes are built. The legacy column shows what the state used to look like - a component that reads as disabled there but not here is a defect, not a stylistic choice.

Where the roles come from. Where the token package names a role for a place, the theme uses it - it does so for 24 components and 125 disabled tokens. Where the package is silent, Blazor's Fluent theme was the next source, and where both are silent the choice is the theme's own and written down.

The two marked rows. CardView's mark is the drop-zone hint, which is invisible until a column is being dragged; ScrollView's is the placeholder text this page puts in the case itself, not something the widget paints. Neither is a defect.

Known gaps, deliberately left. Nine component-scoped opacity dims remain, each named in a ratchet with its reason. Icons drawn as background SVG data-URIs with a baked-in colour cannot be recoloured by any rule - the file manager's refresh icon is one - and that belongs to the component, not to the theme.
