Fluent Next - proposal

Theme modes as CSS classes

Light and dark bundles stay as they are. The proposal is that each bundle also carries the second mode, reachable by a class - so the mode can be switched without swapping the stylesheet, and a block can use the opposite mode.

The stand below runs on the real role values of our blue theme. Switch the mode and watch the counter: the page is already loaded and the stylesheet is never re-fetched - only a class changes.

What this looks like in a bundle

/* dx.fluent-next.blue.light.css - the same light bundle as today */
:root, .dx-theme-mode-light {
  --dxds-color-bg: #ffffff;
  --dxds-color-content: #161616;
  --dxds-color-border: #cbcbcb;
}

/* added: the second mode, reachable by a class */
.dx-theme-mode-dark, .dx-theme-mode-inverted {
  --dxds-color-bg: #242424;
  --dxds-color-content: #ffffff;
  --dxds-color-border: #767676;
}

The dark bundle is the mirror image: dark values on :root, light values reachable by class. The loaded file sets the default, the class switches the mode inside the page, and dx-theme-mode-inverted always means the opposite of the current mode.

What this stand is and is not

The role values and the declaration structure are genuine - taken from our generated design system for the blue theme. The widgets are simplified mockups, not our components: the stand demonstrates the switching and nesting mechanics, not the product look.
