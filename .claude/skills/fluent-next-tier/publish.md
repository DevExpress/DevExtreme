# publish.ts

`tools/naming/publish.ts` regenerates the fluent-next component tier:

- every `fluent-next/<folder>/_public.scss` — the `--dx-*` projections of the component's eligible
  variables, in alphabetical order;
- the collector `fluent-next/_public-tier.scss` — which root selectors (`registries.rootSelectors`)
  carry which component's tier.

```
node tools/naming/publish.ts          # regenerates the tier files   (pnpm run naming:publish)
node tools/naming/publish.ts --check  # exit 1 when a committed file is stale or a rule is broken
```

It needs no built bundle. The rules live in `tools/naming/tier.ts`, which
`tests/fluent-next-naming.test.ts` reads too, so the emitter and the test can never disagree.

## What is generated and what is not

- `_public.scss` and `_public-tier.scss` carry `// GENERATED by tools/naming/publish.ts`. Never edit
  them; change the SCSS variable (or `registries.json` via `OVERRIDES`) and re-run.
- `<folder>/_public-links.scss` is hand-written and never touched by the script; the generated file
  includes it. A relation between two names goes there as a link, the whole value being
  `--dx-a: var(--dx-b);`, so it stays live when `--dx-b` is overridden. The naming test checks that a
  link points at a name declared by the same component or published on `:root`, keeps the state
  (`-hover` → `-hover`), and that an alias reaching another component's root is published as a value,
  not a link.
- Not every variable is eligible: `sassOnly` entries, values a custom property cannot carry (CSS-wide
  keywords, `null`, data-uri images and what they feed), and base-layer wiring are excluded.

## Renames retire public names

The published name is derived from the SCSS variable, so renaming a variable retires a public
`--dx-*` name, and the diff looks like plain regeneration. Record the retirement in
`tools/naming/public-renames.json` in the same pull request; `tests/public-renames.test.ts` keeps a
retired name from reappearing, as an alias or otherwise. Whether an entry is due (only names that
shipped) and how to write it: the journal section of [tokens-update.md](tokens-update.md).

## Failures

- **`fluent-next/<folder>/_public.scss is stale` … `run pnpm naming:publish`** — a declaration file
  changed and the tier was not regenerated, or a generated file was edited by hand. Run
  `pnpm run naming:publish` and commit the result.
- **`X publishes from folder/ but has no rootSelectors — add it to derive-registries.ts
  OVERRIDES`** — only the components in `migrated` and `systemTier` publish, and the generator gives
  each of them a root, so this means `registries.json` is stale or was edited by hand. Make the change
  in `OVERRIDES` (add `rootSelectors` there if the default `.dx-<component>` is wrong), then
  `pnpm run naming:registries` and `pnpm run naming:publish`.
- The naming test reports `not published — run pnpm naming:publish` or `the variable is excluded from
  the tier` for the same causes.
